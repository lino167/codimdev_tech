Guia do plugin codimdev-sites · v0.1

Diga o negócio, aprove o briefing e o plugin leva o site até a conferência.

O codimdev-sites é o meu fluxo de criação de sites com movimento. Ele começa pelas imagens, descobre o movimento nelas e só depois escreve o código. Eu paro uma vez, para aprovar o briefing.

3. MovimentoO roteiro tirado das imagens
4. PromptOs 7 blocos, com números
5. CódigoNext.js com o kit de movimentos
6. ConferênciaPrints comparados com as imagens

A instalação leva um clique e vale para todas as conversas.

  1. Abra o arquivo do plugin

    Na conversa, clique no cartão codimdev-sites.plugin para ver os arquivos.

  2. Aceite a instalação

    Clique no botão de aceitar. As 6 skills passam a aparecer na sua lista.

  3. Confira os conectores

    O Higgsfield precisa estar ligado para gerar imagens. Sem ele, o plugin entrega os prompts para eu gerar em outra ferramenta.

Um projeto começa com uma frase que diz o negócio.

O plugin reconhece o pedido e conduz o fluxo inteiro. Quanto mais eu disser na primeira frase, menos ele pergunta.

Criar um site para uma barbearia em Recife que agenda pelo WhatsApp
Fazer uma landing page para a loja de perfumes da Ana. O Instagram é @[perfil]
Novo projeto de site: pizzaria com delivery, cardápio curto, fotos próprias anexadas

Com estes quatro itens em mãos, o briefing sai numa rodada só.

Dados do cliente

Produtos com preço "a partir de", WhatsApp, Instagram, endereço e horário. O que faltar fica marcado para preencher.

Fotos reais

Do produto, do lugar ou da pessoa. Foto real sempre vence imagem gerada; o plugin só gera o que faltar.

Crédito de imagem

Um site pede de 10 a 20 imagens. O plugin mostra o custo antes de gerar no Higgsfield.

Provas verdadeiras

Nota no Google, número de clientes e depoimentos que o cliente autorizou. Nada disso é inventado.

Cada etapa entrega um arquivo que a próxima usa.

Tudo fica numa pasta por cliente. Se eu quiser mudar algo, mudo o arquivo da etapa e peço para refazer dali em diante.

O kit de movimentos cresce um módulo a cada projeto.

São componentes prontos e testados. O plugin copia sem reescrever; quando um site pede um movimento novo, ele cria o módulo e guarda no kit.

Quatro regras valem em todo projeto, sem exceção.

Imagens antes do código. O movimento sai do que as imagens mostram.

Nada inventado. Preço, telefone, nota e depoimento que faltam ficam para preencher.

Nada publicado sozinho. O site vai ao ar só quando eu pedir.

A marca é do cliente. O carmim e o IBM Plex são só da codimdev.

Dúvidas comuns

O Higgsfield está sem crédito. E agora?

O plugin entrega os prompts numerados com o passo a passo: abrir o ChatGPT, colar, baixar e mandar as imagens de volta. O fluxo continua dali.

O cliente não tem fotos.

As imagens são geradas a partir do briefing. Para pessoas, só uso a foto real do cliente; o plugin não gera rosto de ninguém.

Quero mudar algo depois da aprovação.

Peço a mudança dizendo a etapa: "troca a jogada no briefing e refaz daí em diante". As etapas anteriores ficam como estão.

Como publico o site?

Peço "publicar o site". Com o conector da Vercel ligado, o plugin publica e manda o link.

Como transformo o site em post?

Peço o modo de gravação para Reels e gravo a tela no celular. O plugin também pode montar o post no canvas de Instagram da codimdev.
